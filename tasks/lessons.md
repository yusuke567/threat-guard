# Lessons Learned

## 2026-03-31 振り返り

### 🔴 失敗・手戻りパターン

**1. PRマージ済みと誤報告**
- 問題：PR #58を作成した後、マージ操作を実行していないのに「mainは最新です。変更は既にマージ済みです」と誤報告
- 根本原因：
  - PRの「作成」と「マージ」を混同した
  - mainが`b855825`のままなのに、PRのマージコミット`773707e`がmainに含まれているか検証しなかった
  - 「mainがリモートと同期している」を「PRがマージされた」と誤解した
- 次回の対策：
  1. **マージ操作の明示的実行**: `gh pr merge`またはGitHub UIでマージボタンを押すまで「マージ済み」と言わない
  2. **マージ後の検証**: マージ後は必ず`git fetch origin main && git log origin/main -1`でHEADコミットがマージコミットに変わったことを確認
  3. **報告の精度**: 「PRを作成しました」「マージを実行しました」「mainにマージコミットが反映されました」を明確に区別して報告

### 📌 CLAUDE.mdへの昇格候補

1. **PRマージ確認ルール** — PRをマージしたと報告する前に、必ず以下を確認:
   - `gh pr view <PR番号>`で`merged: true`であること
   - `git log origin/main -1`でHEADがマージコミットになっていること

## 2026-03-05 振り返り

### 🔴 失敗・手戻りパターン

**1. Vercelプロジェクトが3つ乱立していた**
- 問題：`brand-shield`、`threat-guard-web`、`brand-shield-preview` の3プロジェクトが存在し、どれが本番か混乱
- 根本原因：プロジェクト作成時に整理せず、試行錯誤で増えた。正式名称（ThreatGuard）への統一もされていなかった
- 次回の対策：プロジェクト作成時に命名規則を決めてから作る。重複を見つけたら即整理

**2. プレビューURL間違い**
- 問題：大塚さんにVercelプレビュー確認依頼時、間違ったプロジェクト（brand-shield）のURLを渡した
- 根本原因：複数プロジェクトの存在を把握せず、最初に見つけたものを返してしまった
- 次回の対策：プレビューURL提示前にVercelプロジェクト一覧を確認し、正しいプロジェクトから取得する。今後は `threat-guard` 1つのみなので再発しにくい

**3. 途中経過の独り言が多い**
- 問題：「ビルド確認:」「ビルド成功。コミット＆push:」等の途中メッセージがスレッドを埋める
- 根本原因：AGENTS.mdの「途中の独り言を減らし、結果報告を厚く」ルールを守れていない
- 次回の対策：作業完了後にまとめて1メッセージで報告。途中経過は5分以上かかる場合のみ
