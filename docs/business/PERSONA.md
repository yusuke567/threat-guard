# ペルソナ定義

## ユーザー像（2パターン）

### ① スタートアップ・中小企業
**所属:** 法務部 AML（アンチマネーロンダリング）対策部署  
**ドメイン知識:** ゼロ（DNS、フィッシング、ドメイン技術の専門知識なし）  
**求めるもの:** 「何が危険か」「何すればいいか」

### ② 大企業・証券会社・暗号資産交換業者
**所属:** システムセキュリティ部 CISO  
**ドメイン知識:** そこそこあり（DNS、フィッシング、ドメイン技術の専門知識あり）  
**求めるもの:** 「技術的根拠」「エビデンス」

## 業務内容

ThreatGuardを利用して以下を行う：

1. **ドメイン脅威調査** — 不審ドメインの発見・一覧化
2. **分析** — 脅威レベルの判定、フィッシングサイトの特定
3. **削除申請** — 悪意あるドメインの停止依頼（業界用語: Takedown Request）
4. **報告** — 調査結果・対応状況のレポート作成

## 報告先

- **金融庁** の担当者
- **同部署の執行役員CLO**（最高法務責任者）
- **取締役会**

## UI方針：プログレッシブ・ディスクロージャー（段階的開示）

**原則：表層は①向け（平易）、深掘りすると②向け（専門的）**

### レイヤー1：メイン画面（①でも迷わない）
- 専門用語を使わず、リスクと行動にフォーカス
- ステータスは 🔴危険 / 🟡要注意 / 🟢対応済み の信号機方式

### レイヤー2：詳細パネル（クリックで展開）
- 技術用語を併記で表示（例：「なりすましサイトの疑い（DNSレコード不一致）」）

### レイヤー3：技術詳細タブ（②向け）
- 生DNS、WHOIS、HTTPヘッダー、SSL証明書
- JSON/CSVエクスポート

## 用語ポリシー

| 場面 | ルール |
|---|---|
| ナビ・メニュー | 日本語のみ（「脅威一覧」「削除申請」「レポート」） |
| アラート・通知 | 平易な日本語 + リスクレベル色 |
| 詳細パネル | 平易表現（技術用語）の併記 |
| 技術タブ | 専門用語そのまま（英語OK） |
| ツールチップ | 専門用語にホバーで説明を出す |
| PDF/レポート | ②向け＝技術用語あり、①向け＝エグゼクティブサマリー付き |

### 用語変換表

| ✕ 使わない | ◯ 使う | 技術タブ等での併記 |
|---|---|---|
| テイクダウン | 削除申請 | 削除申請（Takedown Request） |
| DNSレコード不一致 | なりすましサイトの疑い | なりすましサイトの疑い（DNSレコード不一致） |
| WHOIS匿名化 | 登録者情報が隠されています | 登録者情報非公開（WHOIS匿名化） |
| MXレコード検出 | メール受信が可能な状態 | メール受信可能（MXレコード検出） |

## 設計への示唆

- ①を切り捨てない（初期ターゲット、導入ハードル低い）
- ②を物足りなくさせない（根拠なしではCISOは稟議を通せない）
- 同一UIで両立（段階開示で開発コスト抑制）
- 操作は直感的に、判断に迷わないUI
- レポートはそのまま上層部・当局に提出できる品質
- 「何をすべきか」が明確にわかるガイダンス
